## 3. 产品概述

### 3.1 产品背景

现代生活节奏快，压力大，人们常常忽视情绪波动背后的生理和环境因素。很多时候，负面情绪可能源于简单的生理需求未被满足，如饥饿、疲劳或缺水等。本产品旨在通过系统化的自检问题，帮助用户快速识别情绪波动的潜在原因，并提供相应的改善建议。

### 3.2 产品定位

一款简单易用的单页面网页应用，通过结构化的问题流程，帮助用户发现情绪波动的潜在原因，并给出相应建议。采用纯前端实现，数据存储在浏览器本地存储中。通过 GitHub Pages 发布，确保全球用户都能便捷访问。

### 3.3 目标用户

- 情绪波动频繁的都市人群
- 希望了解自身情绪变化原因的人群
- 寻求简单自我调节方法的人群

### 3.4 产品价值

- **用户价值**：帮助用户快速识别情绪问题根源，提供自我调节方法
- **差异化价值**：采用简单直接的"一问题一解决方案"模式，无需复杂分析
- **可访问性价值**：作为网页应用，无需安装，随时随地可访问

## 4. 产品目标

### 4.1 核心目标

- 帮助用户快速识别异常情绪的可能原因
- 提供针对性的自我调节建议
- 简化自检流程，提高用户体验

### 4.2 成功指标

- 网站月活跃用户数 ≥ 1000
- 自检完成率 ≥ 80%
- 用户问题解决率 ≥ 60%（用户确认建议有效）

| --- | --- | --- | --- |
| 情绪自检 | 自检流程 | P0 | 系统按顺序展示预设的18个自检问题 |

### 5.2 功能详细说明

#### 5.2.1 情绪自检流程

**功能描述**：
用户通过回答一系列预设问题，找出情绪波动的可能原因。

**功能流程**：
1. 用户打开网页，点击"开始自检"按钮
2. 系统展示第一个自检问题
3. 用户选择"是"或"否"
4. 如选择"是"，系统展示针对该问题的建议，并提供"应用建议并结束"按钮
5. 如选择"否"，系统展示下一个问题
6. 如所有问题均回答"否"，系统展示综合建议

**关键规则**：
- 问题按固定顺序展示，不可跳过
- 一旦用户对某问题回答"是"，立即结束问题流程，展示建议
- 每次自检只识别一个最主要的问题

**问题列表**：
1. 我是不是饿了？我今天吃了多少东西，和平时相比较呢？
2. 我是不是渴了？我今天喝了多少水，和平时相比较呢？
3. 我是不是想上厕所了，我有多长时间没有上厕所？
4. 我有没有感觉有点冷？（冷会感到紧张）
5. 我有没有感觉有点热？（热会感到烦躁）
6. 我有没有很长时间保持相同的姿势，导致身体有一点不舒服？
7. 我是不是想洗澡了？有没有感觉身上有细微的难受？
8. 我是不是累了？今天的体力和脑力使用到什么程度了，做了多少事？
9. 我有没有睡好？昨天的睡眠是否充足？最近一段时间的睡眠是否充足？
10. 我是不是快来月经了？上次来月经是什么时候？
11. 我有没有喝咖啡、茶或者功能饮料？有没有摄入咖啡因或者其他会引起情绪变化的物质？
12. 这种异常情绪是否从今天的某一个时间段开始？是否从某段与他人的互动开始？
13. 我是否有未完的工作？是否有准备做但拖延许久的事物？
14. 我是否住在不方便、不干净、不宜居的环境中？我的屋子脏吗？
15. 我是不是本周内没有适当锻炼？
16. 我是否本周内没有充足的户外活动？
17. 我是否本周内没有与人进行一定的社交？
18. 我是否两个周内没有尝试新的东西，没有获得新的经验？

#### 5.2.2 建议展示

**功能描述**：
针对用户选择的问题，提供相应的具体建议。

**功能要点**：
- 每个问题对应一个或多个具体建议
- 建议内容简洁明了，易于执行
- 对于涉及医疗的问题，明确标注非医疗建议，建议就医

**建议示例**：
- 问题1（饥饿）：建议立即进食，优先选择复合碳水化合物和蛋白质，避免过多糖分
- 问题9（睡眠不足）：建议今晚提前休息，保证7-8小时睡眠；长期睡眠问题建议咨询医生

#### 5.2.3 历史记录

**功能描述**：
记录用户的自检历史，帮助用户了解自己的情绪变化模式。

**功能要点**：
- 记录每次自检的日期、时间
- 记录识别出的问题和对应建议
- 按时间倒序排列，最新记录在前
- 点击记录可查看详情

**数据存储**：
- 使用浏览器的 localStorage API
- 存储格式：JSON数组

## 6. 用户界面

### 6.1 界面流程

```
首页 → 问题页 → 建议页 → 结束页
  ↓                      ↑
历史记录页 ←――――――――――――――
```

### 6.2 界面原型

#### 6.2.1 首页

**界面元素**：
- 应用名称和简介
- "开始自检"按钮（主按钮）
- "历史记录"入口（次要按钮）

**交互说明**：
- 点击"开始自检"进入问题页
- 点击"历史记录"进入历史记录页

#### 6.2.2 问题页

**界面元素**：
- 问题文本（居中显示）
- "是"按钮（主要按钮）
- "否"按钮（次要按钮）
- 进度指示器（如"3/18"）

**交互说明**：
- 点击"是"进入建议页
- 点击"否"显示下一个问题
- 如已是最后一个问题，点击"否"进入综合建议页

#### 6.2.3 建议页

**界面元素**：
- 问题回顾
- 建议内容（分条列出）
- "应用建议并结束"按钮（主要按钮）
- "这不是我的问题，继续检查"按钮（次要按钮）

**交互说明**：
- 点击"应用建议并结束"保存记录并返回首页
- 点击"这不是我的问题，继续检查"返回问题页，显示下一个问题

#### 6.2.4 历史记录页

**界面元素**：
- 历史记录列表（每条包含日期和问题概要）
- 返回按钮

**交互说明**：
- 点击记录项查看详情
- 点击返回按钮返回首页

## 7. 技术实现

### 7.1 开发环境

- HTML5 + CSS3 + JavaScript
- 不依赖任何外部框架，纯原生实现

### 7.2 技术架构

- 纯前端开发，无需后端服务
- 单页面应用（SPA）设计
- 响应式布局，适配各种设备

### 7.3 数据存储

- 使用浏览器的 localStorage API
- 存储内容：用户自检记录（日期、问题、建议）

### 7.4 代码结构

```
index.html          // 主页面文件，包含所有功能
├── CSS 样式        // 内联在 HTML 中
├── JavaScript 代码 // 内联在 HTML 中
└── 数据配置        // 问题和建议数据
```

## 8. 项目实施

### 8.1 开发计划

| 阶段 | 时间 | 内容 |

- **功能测试**：验证所有功能点是否正常工作
- **用户体验测试**：邀请5-10名目标用户进行体验测试
- **兼容性测试**：在不同浏览器和设备上测试

## 9. 风险评估

| 风险 | 影响 | 可能性 | 应对措施 |
| --- | --- | --- | --- |
| 用户对非专业建议产生依赖 | 高 | 中 | 明确标注非医疗建议的性质，严重情况建议就医 |
| 本地存储数据丢失 | 中 | 中 | 提供数据导出功能，提醒用户及时备份 |
| 浏览器兼容性问题 | 中 | 低 | 使用广泛支持的基础特性，做好兼容性测试 |

## 10. 后续规划

### 10.1 迭代方向

- 提供高级分析功能的付费版本
